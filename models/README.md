# Blender source and art pipeline

## Prototype 04 character art

`bestiary.blend` contains five editable scenes: SENTINEL, LANCER, DRONE, KING, and MOTHER. Each has a hierarchical rig, materials, camera, lights, and eight keyed poses (walk 1–4, anticipation 5–6, strike 7, recovery 8). `assets/bestiary-preview.png` is the contact sheet.

To export edits without rebuilding the models:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background models/bestiary.blend --python tools/export_bestiary.py
python tools/pack_bestiary.py
```

To rebuild the bestiary from the authored modeling script, run Blender with `--background --python tools/build_bestiary.py`, then run the packer. This replaces `bestiary.blend`.

The Wanderer's 40-pose atlas is sampled from the rig in `echo-fall.blend`, with interpolated poses, a cyclic running seam, and eight sitting poses (atlas frames 32–39):

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background models/echo-fall.blend --python tools/render_wanderer_smooth.py
python tools/pack_wanderer_smooth.py
```

The main sprite packer preserves both additional manifests when regenerating `art-manifest.js`. After editing the Wanderer source, rerender the smooth atlas too.

## World and original character source

Open `echo-fall.blend` in Blender. It contains six named scenes, selectable from Blender's scene menu:

1. **WANDERER / animated source** — an editable mesh character with a simple hierarchy of FK controls, ceramic armor, an emissive visor, a scarf, mantle, and sword.
2. **RUIN / pointed arch** — individual masonry blocks, metal insets, runes, and rubble.
3. **RUIN / choir spire** — a tower, buttresses, slit windows, and suspended monolith.
4. **RUIN / floating ledge** — a modular stone platform with a broken underside.
5. **MAP / four-area blockout** — the original four areas, with collision blocks, markers, and linked instances of the architecture.
6. **MAP / interconnected world** — the current twelve-room network, including climbable solid walls, pogo-route hazards, rest markers, and portal destinations. Use this scene for current map edits; scene 05 preserves the earlier layout.

## Animation

The character faces **+X**. Controls are named `RIG / ...`; rotate the hips, knees, shoulders, and elbows around local Y. The exported sheet has 16 cells, each 192 × 192 pixels:

| Blender frames | State |
|---|---|
| 1–4 | Idle |
| 5–12 | Run |
| 13 | Jump / dash |
| 14–16 | Attack |

The camera is orthographic and each PNG is transparent. `manifest.json` records the projected foot anchor, so poses share a consistent position in the game. The game mirrors the sprite for left movement. Preserve the camera dimensions and frame layout when editing poses.

## Map editing

Each map collection has `game_zone_id`, `game_area_index`, `game_width`, and origin offsets. Rooms occupy separate grid cells; subtract `game_origin_x` when converting Blender X into game pixels. The exporter does this automatically.

- **1 Blender unit = 100 game pixels.**
- X minus the collection's `game_origin_x` maps to horizontal game position.
- Z = `(452 - game Y) / 100`; the ordinary ground top is Z = 0.
- Objects tagged `role = collision` export their position and dimensions into the game. Keep them axis aligned and preserve their `floor`, `platform`, or `wall` name prefix. Floors and walls are solid; platforms can be jumped through from below.
- Objects tagged `memory-dependent` mark the conditional bridge and ledge. Their activation is still authored in `game.js`.
- Routes, interactions, hazards, enemy spawns, and boss arenas are authored in `data/world.json`, generated by `tools/build_world.py`. They do not move automatically when you move a decorative Blender marker.
- Architecture is decorative and has no automatic collider.

## Export edits without rebuilding the source

From the project directory, in PowerShell:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background models/echo-fall.blend --python tools/export_blender_assets.py
python tools/pack_sprites.py
```

For collision-only edits, append `-- --layout-only` to the Blender command. Then run the packer to update the browser manifest. The export reads the saved model and does not overwrite it.

Refresh the game and start a new run. `assets/art-manifest.js` supplies the exported collision data without requiring fetch or a web server. The original vector figures and geometry remain a fallback if the art bundle cannot load.

## Recreate the original models

`tools/build_blender_assets.py` regenerates the procedural source, saves `models/echo-fall.blend`, and renders all PNGs. **This rebuild replaces the source model; preserve your edited .blend under another name first.** The normal export command above preserves your edits.

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --threads 6 --python tools/build_blender_assets.py
python tools/pack_sprites.py
```

The generator uses Cycles on the CPU with 24 samples and denoising. The atlas packer uses Python's standard library; no Python packages are needed.

To regenerate the current network from `tools/build_world.py` after changing its room specifications:

```powershell
python tools/build_world.py
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background models/echo-fall.blend --python tools/update_blender_world.py
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background models/echo-fall.blend --python tools/export_blender_assets.py -- --layout-only
python tools/pack_sprites.py
```

This replaces scene 06 with the authored network while preserving the character, ruin, and original map scenes. Exported geometry is matched by room ID. Rebuilding only the character and ruins with the older generator requires rerunning the network steps above afterward.
